# Проверяемое чтение и диагностика

Выпуск 0.3.0 добавляет девять инструментов на чтение. Они доступны в `live`,
`discovery`, `admin` и `full`. Запись в Alterios не выполняется. Выгрузка сохраняет
локальные файлы под `ALTERIOS_MCP_ARTIFACTS_DIR`; этот приватный каталог нельзя
добавлять в публичный Git. Нужны явные `profile` и `project_id`.

## Инвентаризация, поиск и связи

1. Вызвать `alterios_export_dataset` с `kinds`, например
   `["content_types", "fields", "views", "forms", "scripts", "diagrams", "reports", "contents"]`.
2. Для полных форм/отчётов и сущностей/колонок представлений указать
   `include_details=true`. По умолчанию читаются только list-маршруты.
3. Проверить `complete`, ошибки каждого раздела и лимиты. При неполном ответе
   нельзя делать вывод об отсутствии объектов. При необходимости увеличить
   ограниченный бюджет и повторить выгрузку.
4. Передать возвращённый `snapshot_id` в `alterios_find_usages` с `query` либо
   в `alterios_relation_graph` с необязательным `root_id`.

Снимок привязан к профилю и проекту. Поиск работает локально и возвращает точные
JSON Pointer пути, а не целые скрипты. Граф связывает точные значения ID;
он не доказывает смысл бизнес-связи и не обнаруживает вычисляемые ссылки в коде.
Фрагменты, колонтитулы и другие записи шаблонов попадают в анализ при включении
их раздела `contents`. Недоступные детали помечаются ошибками.

`alterios_read_all_objects` возвращает ограниченную выборку без сохранения снимка.
Фильтры: `_id`, `contentTypeId`, `diagramId`, `processId`, `contentId`.
Это параметры штатных list-маршрутов; поддержка конкретного фильтра зависит от
типа объекта и версии сервера. Клиент не утверждает, что сервер применил фильтр,
если это не подтверждено возвращёнными данными.

Пагинация не считает короткую страницу концом выборки: сервер может ограничивать
размер страницы. Чтение завершается по счётчику или пустой странице; повтор ID,
изменение счётчика, ошибка и исчерпание бюджета дают `complete=false`.
Маршруты `fields`, `groups`, `helps`, возвращающие простой массив без счётчика,
читаются один раз по их непостраничному контракту. Лимит строк всё равно проверяется.
Без snapshot isolation на сервере одинаковое количество не гарантирует, что
значения не менялись во время чтения. Снимок сообщает время начала/окончания.

## Представления

`alterios_diagnose_view` читает определение, соединения и поля, затем сравнивает
обычную и упрощённую выборки. Если передан `content_id`, дополнительно читает
варианты `contentId` и `dataId: [id]`. Каждая проверка имеет время, ответ или
ошибку. Совпадение ограниченных выборок не доказывает равенство фильтров;
различие служит основанием для проверки привязки формы. Это не SQL EXPLAIN,
не проверка всех записей и не проверка прав другой учётной записи.

## Файлы

`alterios_list_files` выполняет только `elFinder open` для одной папки.
Произвольные команды файлового менеджера не принимаются. Полный обход дерева
не выполняется автоматически. Полученные файловые идентификаторы передаются
в `alterios_download_files`; совместимость elFinder hash с file-ID маршрутом
зависит от сервера и должна проверяться по манифесту.

Скачивание ограничено количеством файлов и байтами. Допускается только штатный
авторизованный маршрут `/api/file/download/{id}`; редиректы запрещены, чтобы не
передать заголовки авторизации другому серверу. HTML-ответ считается возможной
страницей входа и отклоняется; для выгрузки настоящих HTML-файлов нужен отдельный
подтверждённый контракт. Локальные имена имеют вид `0001.bin` и не строятся из
удалённых имён. MIME, ID, размер и SHA-256 записаны в `manifest.json`. Файлы
перечитываются после записи. Частичный экспорт сохраняет ошибки и успешные файлы.

## Журнал и уведомления

`alterios_audit_log` читает журнал уровня экземпляра `/api/log`, локально фильтрует
по контроллеру и точному ID, включая структурированные JSON в `body`/`args`.
Параметр проекта выбирает явный контекст клиента и не ограничивает историю
журнала этим проектом. `observed_first/last` относятся к прочитанной выборке;
они не являются доказательством срока хранения. Структурированные имена авторов,
email и секреты редактируются; ID автора сохраняется, если присутствует.

`alterios_list_notifications` читает только то, что видит настроенная учётная
запись. Отправка и отметка о прочтении отсутствуют. Наличие строки не доказывает
доставку или просмотр пользователем.

## Несколько серверов MCP

`runtime_info` и preflight больше не объявляют дополнительные stdio-серверы
дубликатами только по количеству. Возвращаются `additional_instance_count`,
`ownership_verified=false` и диагностическое пояснение. Проверка устаревшего
кода и несовпадения fingerprint сохраняется. Очистка через CLI при `--apply`
требует повторяемого `--root-pid` с конкретными проверенными PID. Текущий runtime
и его launcher исключаются. Возраст процесса не доказывает, что он осиротел.

## Границы выпуска и продолжение

Это первый рабочий этап общего плана доработок, а не заявление о закрытии всех
сценариев. Следующие этапы остаются отдельной разработкой:

- интеграция проверки зависимостей в preflight по области конкретного изменения;
- семантическая матрица этапов, бизнес-ответственных и фактических прав;
- трассировка родительских процессов и версий опубликованных схем;
- адресные правки форм, согласованные пакеты изменений и восстановление;
- адаптер проверки DOCX/PDF и повторяемые сценарии приёмки по ролям;
- частичная миграция в заполненный проект, перенос вложений и истории;
- вывод причин дублирования уведомлений и их связь с экземплярами процессов.

Существующие write gates и ограничения профилей сохранены. Новые чтения не
включают административные записи. Для живой приёмки каждого контура нужны
его доступность и реальные разрешения; тесты с подставными ответами не заменяют
проверку серверной версии API.
